# Mobile iOS experience

Notes for the iOS 26 style mobile layer (viewports below 768 px). The audit and the component map are in
[`MOBILE-IOS-PLAN.md`](MOBILE-IOS-PLAN.md).

## Progress

### M0 – Audit and plan

- Inventory, web tells and architecture decisions: `docs/MOBILE-IOS-PLAN.md`.
- Before screenshots: `docs/mobile-before/` (`node tests/visual/capture.mjs --out docs/mobile-before --set mobile`).
- Desktop/tablet baselines for the pixel diff are captured with `--set desktop` into a local folder (not committed,
  ~25 MB).

### M1 – Foundation

- `<head>`: `viewport-fit=cover` without zoom lock, `apple-mobile-web-app-*` metas, `theme-color` per theme with a
  mobile variant (iOS grouped background `#000000` / `#F2F2F7`), manifest background `#000000`.
- Launch screens for 12 iPhone sizes, dark and light (`public/launch/`, generated by `scripts/generate-icons.mjs`
  from `src/lib/ios/launch-screens.json`). A fixed app theme only lists its own colour, "System" lists both with
  `prefers-color-scheme`.
- Boot script in `<head>` (`src/lib/ios/boot-script.ts`): `data-standalone`, Dynamic Type scale `--dt`,
  `data-reduce-transparency` – before the first paint.
- `src/styles/ios.css`: iOS system colours mapped onto the app tokens, iOS text styles (SF system font, 17 px body,
  scaled by `--dt`), solid cards with 22 px radius, no tap highlight, `touch-action: manipulation`, no selection or
  callout on chrome, 16 px+ form fields, focus rings only for keyboard focus, safe-area variables
  (`--sat/--sab/--sal/--sar`), spring easing tokens.
- `IosRuntime` (`src/components/ios/ios-runtime.tsx`): keyboard inset `--kb`, standalone flag, pinch-zoom lock in
  standalone (except `[data-allow-zoom]`), focused field kept above the keyboard.
- `src/lib/ios/haptics.ts`: switch-input haptics (iOS 18+) with `navigator.vibrate` fallback.
- Hooks: `useStandalone`, `useScrollDirection`, `useKeyboardInset`, `useReducedTransparency`.
- Desktop/tablet pixel diff: only time-dependent content differs (current time, session count, build date).

### M2 – Liquid Glass

- Material tokens and classes in `src/styles/ios.css` (`.glass`, `--clear`, `--prominent`, `--capsule`,
  `--circle`): backdrop blur + saturate + brightness, adaptive tint, gradient rim (masked `::before`), specular
  sheen following the finger (`::after`, `--lx/--ly`), soft wide shadow. Tokens follow the app theme
  (Dunkel/Hell/System), not only the system colour scheme.
- `GlassSurface` / `GlassButton` (`src/components/ios/glass.tsx`) are the only way glass is created. Press:
  spring scale to 1.08 and full sheen on touch-down, spring back on release (CSS `linear()` spring, interruptible
  because transitions retarget from the current value). Only `transform` and `opacity` animate.
- Reduce Transparency: `prefers-reduced-transparency: reduce` and the new switch "Transparenz reduzieren"
  (Einstellungen → Darstellung, phone layout only, stored in `localStorage`) turn every glass element into a solid
  cell with a separator outline. `prefers-contrast: more` raises tint opacity and rim strength.
  `prefers-reduced-motion` disables the press scale.

### M3 – Navigation chrome

- `GlassTabBar` (`src/components/ios/tab-bar.tsx`): floating glass capsule (16/20 px inset, bottom
  `max(safe-area − 8, 12)`, 62 px) with Übersicht / Trades / Journal / Mehr and a selection pill (concentric 27 px
  radius) that slides with a spring and stretches like a droplet in the direction of travel. Dragging a finger
  across the capsule scrubs between tabs (pill follows the finger, haptic per step, commit on release). Separate
  prominent glass "+" circle for "Neuer Trade". Scrolling down > 40 px collapses the capsule into a circle with the
  active icon (transform/opacity only); scrolling up or tapping the circle expands it. Hidden while the keyboard is
  open (`[data-keyboard]`) and while a large sheet is presented (`[data-sheet-large]`).
- Tab behaviour: each tab remembers its last screen and every screen its scroll position
  (`src/lib/ios/nav-memory.ts`); switching tabs is instant (no slide) and restores the position; tapping the active
  tab pops to its root, tapping it at the root scrolls to the top.
- `NavBar` (`src/components/ios/nav-bar.tsx`): no solid bar. Glass back circle (pops when the previous screen is the
  parent, otherwise opens the parent), inline title that fades in once the large title scrolled under the bar, one
  glass capsule on the right with the global filter value ("Dieser Monat ▾") and search. Large titles
  (`ios-large-title`, 34 pt) on tab roots and list screens grow slightly on rubber-band overscroll.
- Scroll edge effect: a blurred, masked gradient behind status bar and nav bar fades in when content scrolls under
  it; a subtle gradient sits behind the tab bar. At most 5 backdrop-filter layers are visible (edge, back, capsule,
  tab bar, "+").
- Main content scrolls on the document under the translucent bars; padding keeps it reachable.
- Install hint: solid iOS card above the tab bar with the share glyph.
- The old `bottom-tab-bar.tsx` was removed; the desktop/tablet `TopBar` is hidden below 768 px.

## Deviations from the brief

- Playwright WebKit could not be downloaded in the build sandbox (`cdn.playwright.dev` is blocked there). Local
  checks use Chromium with iPhone profiles (touch, iPhone user agent, DPR 3); the WebKit projects are configured in
  `playwright.config.ts` and run in CI and on the developer's machine.
- `src/proxy.ts`: `/launch/` (launch screen PNGs) is public like `/icons/`, because iOS loads them before any login.
  No auth logic changed.
- Hover: Tailwind 4 already wraps every `hover:` utility in `@media (hover: hover)`, so no extra gating of existing
  components was needed.
