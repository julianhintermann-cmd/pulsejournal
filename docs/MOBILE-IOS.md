# Mobile iOS experience

Notes for the iOS 26 style mobile layer (viewports below 768 px). The audit and the component map are in
[`MOBILE-IOS-PLAN.md`](MOBILE-IOS-PLAN.md).

## Progress

### M0 – Audit and plan

- Inventory, web tells and architecture decisions: `docs/MOBILE-IOS-PLAN.md`.
- Before screenshots: `docs/mobile-before/` (`node tests/visual/capture.mjs --out docs/mobile-before --set mobile`).
- Desktop/tablet baselines for the pixel diff are captured with `--set desktop` into a local folder (not committed,
  ~25 MB).

### M1 – Foundation

- `<head>`: `viewport-fit=cover` without zoom lock, `apple-mobile-web-app-*` metas, `theme-color` per theme with a
  mobile variant (iOS grouped background `#000000` / `#F2F2F7`), manifest background `#000000`.
- Launch screens for 12 iPhone sizes, dark and light (`public/launch/`, generated by `scripts/generate-icons.mjs`
  from `src/lib/ios/launch-screens.json`). A fixed app theme only lists its own colour, "System" lists both with
  `prefers-color-scheme`.
- Boot script in `<head>` (`src/lib/ios/boot-script.ts`): `data-standalone`, Dynamic Type scale `--dt`,
  `data-reduce-transparency` – before the first paint.
- `src/styles/ios.css`: iOS system colours mapped onto the app tokens, iOS text styles (SF system font, 17 px body,
  scaled by `--dt`), solid cards with 22 px radius, no tap highlight, `touch-action: manipulation`, no selection or
  callout on chrome, 16 px+ form fields, focus rings only for keyboard focus, safe-area variables
  (`--sat/--sab/--sal/--sar`), spring easing tokens.
- `IosRuntime` (`src/components/ios/ios-runtime.tsx`): keyboard inset `--kb`, standalone flag, pinch-zoom lock in
  standalone (except `[data-allow-zoom]`), focused field kept above the keyboard.
- `src/lib/ios/haptics.ts`: switch-input haptics (iOS 18+) with `navigator.vibrate` fallback.
- Hooks: `useStandalone`, `useScrollDirection`, `useKeyboardInset`, `useReducedTransparency`.
- Desktop/tablet pixel diff: only time-dependent content differs (current time, session count, build date).

### M2 – Liquid Glass

- Material tokens and classes in `src/styles/ios.css` (`.glass`, `--clear`, `--prominent`, `--capsule`,
  `--circle`): backdrop blur + saturate + brightness, adaptive tint, gradient rim (masked `::before`), specular
  sheen following the finger (`::after`, `--lx/--ly`), soft wide shadow. Tokens follow the app theme
  (Dunkel/Hell/System), not only the system colour scheme.
- `GlassSurface` / `GlassButton` (`src/components/ios/glass.tsx`) are the only way glass is created. Press:
  spring scale to 1.08 and full sheen on touch-down, spring back on release (CSS `linear()` spring, interruptible
  because transitions retarget from the current value). Only `transform` and `opacity` animate.
- Reduce Transparency: `prefers-reduced-transparency: reduce` and the new switch "Transparenz reduzieren"
  (Einstellungen → Darstellung, phone layout only, stored in `localStorage`) turn every glass element into a solid
  cell with a separator outline. `prefers-contrast: more` raises tint opacity and rim strength.
  `prefers-reduced-motion` disables the press scale.

### M3 – Navigation chrome

- `GlassTabBar` (`src/components/ios/tab-bar.tsx`): floating glass capsule (16/20 px inset, bottom
  `max(safe-area − 8, 12)`, 62 px) with Übersicht / Trades / Journal / Mehr and a selection pill (concentric 27 px
  radius) that slides with a spring and stretches like a droplet in the direction of travel. Dragging a finger
  across the capsule scrubs between tabs (pill follows the finger, haptic per step, commit on release). Separate
  prominent glass "+" circle for "Neuer Trade". Scrolling down > 40 px collapses the capsule into a circle with the
  active icon (transform/opacity only); scrolling up or tapping the circle expands it. Hidden while the keyboard is
  open (`[data-keyboard]`) and while a large sheet is presented (`[data-sheet-large]`).
- Tab behaviour: each tab remembers its last screen and every screen its scroll position
  (`src/lib/ios/nav-memory.ts`); switching tabs is instant (no slide) and restores the position; tapping the active
  tab pops to its root, tapping it at the root scrolls to the top.
- `NavBar` (`src/components/ios/nav-bar.tsx`): no solid bar. Glass back circle (pops when the previous screen is the
  parent, otherwise opens the parent), inline title that fades in once the large title scrolled under the bar, one
  glass capsule on the right with the global filter value ("Dieser Monat ▾") and search. Large titles
  (`ios-large-title`, 34 pt) on tab roots and list screens grow slightly on rubber-band overscroll.
- Scroll edge effect: a blurred, masked gradient behind status bar and nav bar fades in when content scrolls under
  it; a subtle gradient sits behind the tab bar. At most 5 backdrop-filter layers are visible (edge, back, capsule,
  tab bar, "+").
- Main content scrolls on the document under the translucent bars; padding keeps it reachable.
- Install hint: solid iOS card above the tab bar with the share glyph.
- The old `bottom-tab-bar.tsx` was removed; the desktop/tablet `TopBar` is hidden below 768 px.

### M4 – Stack navigation

- `src/components/ios/stack.tsx`. Instead of intercepting routes + a parallel `@stack` slot (every detail route and
  its data loading would exist twice), the outgoing screen is frozen as a static DOM copy the moment React removes
  it: `<StackProbe>` is the first child of `<main>`, and its layout-effect cleanup runs while the old DOM is still
  attached and still at its scroll position. This covers every navigation source (links, `router.push`, history).
  The copy is plain inert DOM, so it can never re-read the new URL (the "frozen location" rule) – duplicated,
  half-transparent lists are impossible by construction.
- Push: the new screen slides in from the right over the frozen previous one (−30 % parallax, 12 % dim, edge
  shadow), 500 ms `cubic-bezier(0.32, 0.72, 0, 1)`. Pop: the frozen leaving screen slides out to the right over the
  real previous screen, whose scroll position is restored before the first paint.
- Swipe back (home-screen app only): starts in the left 30 % of the screen, never on inputs, charts, horizontal
  scrollers or swipeable rows; the real screen follows the finger 1:1 over the frozen previous screen; completes
  above 35 % progress or 0.5 px/ms, otherwise springs back. Per-tab stacks keep up to 8 frozen screens.
- Sheet routes (`/trades/new`, `/trades/[id]/edit`) are presented: the previous screen stays visible behind,
  scaled to 0.94, rounded and dimmed (card stack); the route scrolls inside a sheet with 38 px top corners; ✕ in
  the nav bar dismisses (forms can intercept it for a dirty check). Deep links are presented over black.
- Safari tabs and reduced motion get a 150 ms crossfade instead (Safari animates its own edge swipe); tab switches
  are instant.
- Race rules: a touch during a running transition settles it first (the tap lands on the final layout); every
  route commit cancels a running transition before starting the next; layout changes happen after pointer release.
  Stress test (tab tap → row tap after 0–22 frames, 4× CPU throttling, invariants: one screen, no active layers,
  no running animations, the active tab matches the URL): 100/100 passed.

### M5 – Modals and feedback

- `IosSheet` (`src/components/ios/sheet.tsx`) replaces the phone branch of `ResponsiveDialog` (all dialogs):
  detents from the content height (fit/medium ≈ 50 %, large ≈ 92 %), floating glass at medium (8 px inset, 36 px
  radius), attached solid sheet at large with the card-stack effect behind (`[data-dialog-large]`: screen scales
  to 0.94, tab bar and nav bar step away). Grabber + header (✕ glass circle, centred title, optional ✓ prominent
  circle) drag the sheet; content drags it only when scrolled to the top (or while the sheet can still grow), so
  scrolling and dragging hand off seamlessly. Velocity-aware snapping, rubber-band above large, dismiss below the
  lowest detent. `dirty` asks "Änderungen verwerfen?" (action sheet) before closing. The sheet sits above the
  keyboard (`--kb`).
- `ActionSheet` / `IosAlert` (`src/components/ios/action-sheet.tsx`): destructive confirmations are action sheets
  (glass group, red destructive row, separate "Abbrechen"); typed confirmations (backup restore) and
  non-destructive ones are centred glass alerts with capsule buttons. `ConfirmDialog` switches on phones.
- `GlassMenu` (`src/components/ios/menu.tsx`): glass popover that grows out of its button (transform-origin at the
  trigger, spring), checkmarks, trailing icons, sections, destructive rows. The global filter capsule opens it
  (periods + accounts); "Benutzerdefiniert…" opens a sheet with native date pickers.
- `ContextMenu` + `useLongPress`: 450 ms, cancelled after 8 px movement, haptic, lifted static copy of the item
  (scale 1.02, shadow) over a blurred and dimmed backdrop, glass menu next to it.
- Banners: on phones Sonner toasts render as glass capsule banners below the Dynamic Island (3 s, swipe up to
  dismiss, one action such as "Rückgängig"). `CheckmarkHud` (`showCheckmarkHud`, `notifySaved`): centred glass
  square with a drawn ✓ for ~1 s after saving a trade.
- `ActivityIndicator`: iOS 8-spoke spinner; `Redacted` placeholder with a 1.5 s opacity pulse.

### M6 – Lists and gestures

- `src/components/ios/list.tsx`: `InsetGroupedList`, `ListSection` (header, 26 px rounded group, footer),
  `ListRow` (≥ 44 px, leading Settings icon `ListIcon`, value, accessory, chevron in tertiary label, separators
  inset to the text). Press feedback: `ios-fill` on touch-down, fades out 200 ms after release (a document touch
  listener enables `:active` on iOS).
- Mehr: Settings-style list with white glyphs in coloured squares (Kalender red, Statistiken blue, Playbooks orange,
  Konten green, Import/Export and Einstellungen gray) and a red "Abmelden" row.
- `SwipeableRow` (`src/components/ios/swipeable-row.tsx`): row follows the finger 1:1, axis lock after 10 px,
  buttons grow with the swipe, springs on release, one open row at a time, tap elsewhere closes, a full swipe past
  60 % fires the first action with a haptic. Trades: left → Löschen (red, full swipe deletes with the undo banner) +
  Bearbeiten (accent), right → Duplizieren.
- Trades list on phones (`trade-list-row.tsx`): sticky day headers with the day P&L, inset-grouped rows (symbol +
  direction, net P&L + R in secondary label, setup · session · time, 40 px thumbnail), long-press context menu
  (Bearbeiten, Duplizieren, Teilen via Web Share API with a text summary, Löschen). Day groups use
  `content-visibility: auto`. Tablet keeps the cards, desktop the table.
- `PullToRefresh` on Übersicht, Trades, Journal and Kalender: iOS activity indicator behind the large title, haptic
  at 80 px, `router.refresh()` in a transition, content held down until it finished (≥ 600 ms). Uses the native
  rubber band on iPhone (negative `scrollY`), a JS rubber band elsewhere; horizontal gestures are ignored.
- Every web spinner (`Loader2`) is a `Spinner`: the iOS activity indicator on phones, unchanged elsewhere. Skeletons
  become redacted placeholders (flat fill, 1.5 s opacity pulse) on phones.

### M7 – Screens

- Übersicht: greeting line under the large title, `PhoneHero` (net P&L as rolling digits `NumberRoll`, change in
  % as a tinted capsule, full-bleed `ScrubChart` with Stocks-style scrubbing that shows date and value of the point
  under the finger, presets 1W · 1M · 3M · YTD · 1J · Alles as a segmented control mapped onto the global filter).
  KPI cards stay below as glass-free grouped tiles; Letzte Trades (5 + "Alle anzeigen"), Top Setups and Top-Fehler
  are inset-grouped lists.
- Trade erfassen/bearbeiten: presented sheet with ✕ (dirty check → "Änderungen verwerfen?") and a prominent ✓ glass
  button in the nav bar that submits the form; Schnell/Detailliert as an iOS segmented control; the sticky web
  bottom bar is gone on phones. Saving shows the checkmark HUD. Decimal inputs get `enterKeyHint="next"`.
- Trade-Detail: nav bar capsule with ▲/▼ (previous/next trade), Bearbeiten and a "…" menu (Duplizieren, Teilen,
  Löschen); details as iOS info rows (label left, value right, hairline separators); screenshots as a scroll-snap
  carousel with page dots. The lightbox closes with a vertical swipe (overlay fades, image scales) and allows
  pinch zoom (`data-allow-zoom`).
- Journal: "Heute" capsule in the nav bar, days as list rows (mood emoji as icon, `EEE, d. MMM`, note preview,
  day P&L and trade count). The day editor moves the autosave status into the nav bar.
- Statistiken: the tab list becomes horizontally scrolling chips.
- Einstellungen: iOS switches (51 × 31, green), "Transparenz reduzieren" switch.
- Login/Setup: 72 px app icon, centred 34 pt title, `enterKeyHint` next/go so the keyboard walks through the form.
- Tablet and desktop: every phone variant is `md:hidden`, every web variant `max-md:hidden`; the desktop screenshot

### M8 – Accessibility, performance, tests

- Debug overlay: append `?debug=1` to any URL (stays on for the tab, `?debug=0` turns it off). Shows FPS and slow
  frames (> 20 ms), visible glass layers against the budget of 5 (red when over), safe-area insets (red/green dashed
  guides), `--kb` (keyboard), `--dt` (Dynamic Type), viewport and the flags standalone · dark/light ·
  reduced-motion · reduced-transparency · increased-contrast · keyboard · presented. Loaded lazily, nothing is
  rendered without the parameter.
- Playwright projects (`playwright.config.ts`): `iphone-16-pro` (402 × 874 @3x, dark, full suite),
  `iphone-16-pro-light`, `iphone-16-pro-max` (440 × 956), `iphone-se` (375 × 667, light, plus the 320 px run),
  `iphone-16-pro-reduced-motion` and `desktop` (1440/1024/768 guard). All iPhone projects run in WebKit with touch,
  iPhone user agent and DPR; a second server with the demo data (`SEED_DEMO=true`) serves them, the smoke test keeps
  its empty instance. CI installs Chromium and WebKit and runs everything.
- Specs (`tests/e2e/ios/`):
  - `navigation`: tabs and `aria-current`, push/pop with scroll memory, edge swipe (complete and cancel), tap on
    the active tab scrolls up, large title → inline title, the stack race (20 rounds of tab + row taps at random
    frame offsets, CPU ×4 in Chromium).
  - `modals`: + presents the trade sheet with the card stack, dirty form asks before discarding, form sheet
    opens large and drag-dismisses, dirty sheet asks before a swipe closes it, delete asks with an action sheet.
  - `lists`: swipe actions both edges, full swipe deletes with undo, long-press menu, pull to refresh, chart
    scrubbing, range presets.
  - `layout` (all four phone projects): no horizontal scroll on 14 screens (and at 320 px), ≤ 5 glass layers
    (read from the debug overlay), every interactive element has a name, 44 pt targets in the chrome, fields ≥ 16 px
    (no zoom on focus) with `enterkeyhint`, keyboard inset → `--kb` and the tab bar moves away, WCAG AA text contrast.
  - `reduced-motion`: push/pop use no translate keyframes, the edge swipe is off.
  - `desktop`: no phone chrome, stack layer or presented state at 1440/1024/768, root font size unchanged.
- Gestures: in Chromium the `finger` fixture sends real touches through CDP; WebKit has no touch-move API, so it gets
  synthetic pointer + touch events on the touched element (implicit capture). The synthetic path is verified in
  Chromium with `SYNTHETIC_TOUCH=1`.
- Findings fixed by the suite: the dashboard hero glow widened the page by 20 px (the fixed nav bar grew with it and
  cut off its trailing button); form sheets (Konto, Buchung, Playbook, Instrument) now ask "Änderungen verwerfen?"
  before a swipe or ✕ discards input; light mode text colours raised to WCAG AA (see deviations).
- Desktop/tablet: `python3 tests/visual/compare.py BEFORE AFTER` on two `capture.mjs --set desktop` runs. Only the
  known dynamic regions differ (time-of-day greeting, current time in the trade form, build date and session count
  in Einstellungen, the stats charts that render a frame differently between runs).
- After screenshots: `docs/mobile-after/`; side by side: `docs/mobile-compare-dark.jpg`, `docs/mobile-compare-light.jpg`.

## Running the checks

```sh
pnpm lint && pnpm typecheck && pnpm test            # static checks and unit tests
pnpm test:e2e                                        # smoke + iPhone suite (WebKit) + desktop guard
IOS_BROWSER=chromium pnpm test:e2e                   # where WebKit cannot be installed
pnpm exec playwright test --project=iphone-se        # one device
STACK_RACE_ROUNDS=100 pnpm exec playwright test -g "broken stack"
node tests/visual/capture.mjs --base http://localhost:3000 --out docs/mobile-after --set mobile
```

On Windows: `pnpm exec playwright install webkit` once, then the same commands; `--browser webkit` for
`capture.mjs`.

## Manual check on an iPhone

Playwright WebKit is not iOS Safari: blur rendering, the software keyboard, haptics, rubber banding and the
home-screen app need a device. Before a release, on an iPhone with iOS 26 (Safari and the app from the home screen):

1. Install: Safari → Teilen → Zum Home-Bildschirm. Launch screen in the right colour (dark/light), no white flash,
   status bar readable on both themes.
2. Tab bar: tabs switch instantly, the pill follows a scrub with a haptic tick, scrolling down collapses the bar,
   the + button opens the quick trade sheet.
3. Stack: open a trade, swipe back from the left edge (slow + cancel, fast flick), the list keeps its position;
   tapping the active tab scrolls up.
4. Sheets: global filter (medium detent, drag up to large), Neues Konto (large, card stack behind), typing then
   swiping down asks "Änderungen verwerfen?". The keyboard pushes the sheet up and the focused field stays visible.
5. Trades list: swipe left/right, full swipe delete + Rückgängig in the banner, long press menu with the preview,
   pull to refresh with a haptic at the threshold.
6. Übersicht: scrub the chart (number and date follow, haptic on start), range presets.
7. Trade form: Schnell/Detailliert, decimal keyboard with "Weiter", ✓ saves with the checkmark HUD; no zoom on any
   field.
8. Screenshots: carousel swipe, lightbox pinch zoom, swipe down to close.
9. Settings → Bedienungshilfen: Bewegung reduzieren (crossfades, no edge swipe), Transparenz reduzieren (solid
   chrome), Kontrast erhöhen (stronger rims), Textgrösse gross (layouts reflow, nothing clipped), VoiceOver (tab bar,
   back button, rows and menus are announced with names).
10. Rotate to landscape: safe areas left/right respected, nothing behind the Dynamic Island.
11. `?debug=1`: FPS stays near 60 (120 on ProMotion) while scrolling the trades list, glass layers ≤ 5.

## Accessibility results

- Text contrast (WCAG AA, 4.5:1, large text 3:1) passes on every checked screen in dark and light, checked by the
  `layout` spec. The brand accent (prominent buttons, accent labels) is held to 3:1 like Apple's tint colour.
- Every visible button and link has an accessible name; swipe actions are reachable through the context menu and the
  detail screen; the debug overlay and decorative layers are `aria-hidden`.
- Reduced motion, reduced transparency and increased contrast are honoured (system settings and the in-app switch
  "Transparenz reduzieren").
- Dynamic Type: iOS text styles scale with the system text size (`--dt`, 0.82–1.35).

## Deviations from the brief

- Playwright WebKit could not be downloaded in the build sandbox (`cdn.playwright.dev` is blocked there). Local
  checks use Chromium with iPhone profiles (touch, iPhone user agent, DPR 3); the WebKit projects are configured in
  `playwright.config.ts` and run in CI and on the developer's machine.
- `src/proxy.ts`: `/launch/` (launch screen PNGs) is public like `/icons/`, because iOS loads them before any login.
  No auth logic changed.
- Floating vs. attached sheet: the 8 px side inset and radius switch with the detent (no animated width), the
  height change itself is a `transform` spring.
- Swipe actions are `aria-hidden`; VoiceOver users reach the same actions through the long-press menu and the
  detail screen.
- Hover: Tailwind 4 already wraps every `hover:` utility in `@media (hover: hover)`, so no extra gating of existing
  components was needed.
- Kalender: the month pager keeps the existing horizontal swipe instead of a vertically scrolling year of months
  (the calendar data is loaded per month; a continuous scroll would need new queries).
- CSV import stays an inline step wizard on the Import/Export screen instead of a sheet; the wizard has four steps
  with previews that need the full screen height.
- Theme choice in Einstellungen stays a segmented control in the row instead of a pushed selection list.
- The lightbox fades and scales on dismiss instead of flying back into the exact thumbnail frame.
- Colours, light mode: Apple's systemGreen (#34C759) and systemRed (#FF3B30) reach only 2.0:1 and 3.2–3.6:1 as text
  and secondaryLabel (60 60 67 / 0.6) 3.4:1 on grouped grey. Phones use #1B6E30, #D70015 (Apple's Increase Contrast
  red) and secondaryLabel at 0.74 instead. Dark mode uses Apple's Increase Contrast red #FF6961 (#FF453A is 4.0:1 on
  its own tint). Calendar heat cells show their numbers in the label colour on phones (with a light shade in dark
  mode); the tint and the sign carry the direction.
- White text on the brand accent (#4F7CFF / #3B63E6) is 3.7–3.8:1, below 4.5:1 for small text – the same as Apple's
  own prominent buttons on systemBlue. Kept for the brand; held to 3:1 in the contrast test.
- Playwright WebKit gestures are synthetic events (no touch-move API in WebKit); the real-touch path runs in Chromium.
